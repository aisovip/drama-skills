改编不是把原文缩短，也不是为短剧补一套流行结构。目标是保留原材料真正承担的戏剧功能，
再为屏幕、单集边界和制作条件寻找新的载体。

## 1. 先建立改编契约

| 类别 | 含义 | 处理 |
|---|---|---|
| 不可改承诺 | 核心关系、关键选择、结局含义、必要世界规则 | 保持事实与功能 |
| 可换载体 | 叙述顺序、场景、配角、信息出现方式 | 可压缩/合并，但记录替代关系 |
| 可删冗余 | 重复说明、只连接路程的段落、无新状态的复述 | 删除并说明没有损失什么 |
| 未决歧义 | 原材料本身矛盾或授权不清 | 保留问题，不替作者定案 |

不要把“更短”当作唯一目标。删掉的段落可能很短，却承担信任转变；保留的奇观可能很长，
却没有推动人物选择。

## 2. 用功能账本压缩

**`STY-07 · reviewed_invariant`**：人物或场景合并必须保留戏剧作用、知情范围、
关系位置和因果桥；“人更少”不能单独证明合并成功。

为候选人物、场景和信息记录它承担的功能：

- 谁迫使主角作选择；
- 谁持有证据、秘密、资源或社会许可；
- 哪个场景改变权力、知识、关系、风险或物理状态；
- 哪段建立后续兑现所需的误信/承诺；
- 哪个空间限制让冲突必须现在发生。

### 合并人物

只有当两个角色的功能可以由同一人的目标、知识范围和关系位置自洽承担时才合并：

1. 两人是否原本知道不同事实？合并后会不会提前泄密？
2. 两人是否分别代表支持与压力？合并后对抗是否消失？
3. 两段关系是否需要不同历史/伦理位置？
4. 同一演员在同一时点能否完成两项行动？
5. 合并后某个背叛、证言或牺牲是否失去代价？

弱合并：“配角太多，所以把两个人改成同事甲。”
可用合并：“门店会计与房东都阻断账本获取；改为房东兼代账人，但把原会计掌握而房东
不知的假发票来源转给另一条证据链。”

### 合并场景

场景可合并需同时满足：时间/地点能连续、两个议程可以同场碰撞、信息出现不改变因果顺序、
合并后每个关键反应仍有空间。不能只因“都在办公室”就把隔日后果塞进同一分钟。

## 3. 信息视觉化阶梯

**`STY-08 · craft_default`**：优先尝试有后果的行为、证据、空间压力或对话策略，
再决定是否保留中性说明。

将“人物知道/回忆/解释”依次尝试转成：

1. **行动后果**：他不报门牌，直接用旧钥匙开门；
2. **可争夺证据**：缺页、录音、伤痕、持物、屏显；
3. **空间行为**：谁挡出口、谁避开座位、谁能触到证物；
4. **对话策略**：试探、误导、讨价、逼供、拒绝，而非中性说明；
5. **声音/主观表达**：VO/OS/主观画面，只有作品明确选择时使用。

视觉化不等于“每句话配一个动作”。来回倒水、走窗边、翻无关文件若不改变议程或证据条件，
只是制造假运动。

## 4. 保住因果桥

压缩时间后逐项检查：

~~~text
原因事实 -> 人物理解 -> 选择 -> 对手反制 -> 可见后果 -> 新压力
~~~

若删除的段落承担“人物为何相信”“对手如何得知”“道具如何到手”，需在新版本建立等价且
可见的桥，不能用一句“原来如此”跳过。

大幅重排时写改编功能对应表：

~~~json
{
  "source_function": "<原功能，不复制长原文>",
  "new_carrier": "<新人物/场景/证据/动作>",
  "preserved": ["<承诺/因果/关系>"],
  "lost_or_changed": ["<可能损失>"],
  "status": "proposed | creator_accepted | unresolved"
}
~~~

## 5. 单集化而不肢解

短剧单集应完成一个局部状态变化，同时保持长线：

- 当集兑现原材料的一部分吸引力；
- 结尾压力由本集选择/后果产生；
- 不靠把一个完整反应切掉来制造“卡点”；
- 下一集的进入状态是精确事实，不是“局势更紧张”。

可把一段长叙事拆成多集，但每集都要回答“本集观众具体得到了什么”。

## 6. 规则分级与审查

- `structural_invariant`：来源与功能对应表、授权边界、铺垫、兑现和交接引用都能解析。
- `reviewed_invariant`：合并没有造成知情穿帮，压缩没有删断因果，新的表现方式保留核心含义。
- `craft_default`：优先用选择、证据和空间后果承载说明；有明确风格理由时可以调整。
- `taste_option`：保留旁白、倒叙、多声部人物、慢场或开放结尾均是创作者选择。

审查时引用“原功能 → 新载体 → 损失/保持”，不要用与原材料的表面相似度代替判断。
